---
description: 作業内容を自分の GitHub リポジトリに保存する（commit と push）
---

作業内容を GitHub に保存します（`git commit` と `git push`）。次の手順を **この順番どおりに** 実行してください。

コミットメッセージの指定（コマンド引数）: `$ARGUMENTS`

> **これは「提出」ではありません。** 保存しても、主催者に作品が提出されたことにはなりません。提出は `/submit` で行います。参加者に聞かれたら、そう伝えること。

## 手順 1: 保存先を確認する

```bash
gh repo view --json nameWithOwner,url
```

表示された `nameWithOwner` を確認する。

## 手順 2: 講師のリポジトリなら、保存せずに止める

`nameWithOwner` が **`kzkski/cloudflare-dev-container`**（大文字・小文字は区別しない）なら、**何も保存せずに止める**。次のように伝えて、この手順を終了する。

> ここは講師のリポジトリから作った作業部屋なので、保存できません。自分のリポジトリから作業部屋を作り直してください。

## 手順 3: 変更を確認する

```bash
git status
```

- 変更がなければ「保存する変更がありません」と伝えて、**終了する**（コミットも push もしない）。
- `.env` や認証情報、鍵のような **秘密情報らしいファイル** が保存対象に含まれていたら、`git add` せずに参加者に伝えて確認する。

## 手順 4: commit する

1. すべての変更を追加する。

   ```bash
   git add -A
   ```

2. 変更内容を要約した、**日本語の短いコミットメッセージ**で commit する。上の `$ARGUMENTS` に指定があれば、それをメッセージとして使う。

   ```bash
   git commit -m "（変更内容を要約した短いメッセージ）"
   ```

## 手順 5: push する

```bash
git push
```

push に失敗したら、**表示されたエラーをそのまま参加者に伝えて、終了する**。別の方法は試さない。

## 手順 6: 結果を伝える

- 保存した **ファイルの一覧**（コミットに含まれたファイル）
- **リポジトリの URL**（手順 1 の `url`）

を参加者に伝える。

## 守ること

- 次のことは **しない**。
  - `git push --force` など、履歴を書き換える操作
  - `git remote` の変更
  - `gh auth login` / `gh auth logout` の実行
  - `gh repo create`、リポジトリの設定の変更、公開範囲の変更
  - `GITHUB_TOKEN` や認証情報の表示
- push に失敗しても、トークン付きの URL に変えるなど、**独自に別の手段で push しようとしない**。
- 保存と提出は別物。保存しただけで、提出（`/submit`）はしない。
